# Тест настоящей boot-анимации Arasaka

Эксперимент рассчитан на конкретные версии bootmgfw 28000.342 и winload 26100.9949 этого ASUS. Он заменяет кадры штатного индикатора Windows в памяти во время загрузки. Большой красный логотип остаётся статичным; маленький белый знак под ним анимирован. Красный цвет маленького индикатора пока не реализован.

Пакет прошёл запуск Windows RE в QEMU с Secure Boot, оригинальным HackBGRT и точной версией winload ноутбука. Загрузка установленной Windows, её драйверов/VBS и FACEIT на физическом ASUS ещё требует проверки. Ноутбук автоматически не перезагружался.

## Первый запуск

1. Сохранить работу. На рабочем столе запустить `Test-Arasaka-Animation.cmd`. После нажатия клавиши он выставит только **одну** следующую загрузку через экспериментальную запись и перезагрузит компьютер без принудительного закрытия приложений.
2. При первом запуске ожидается `Verification failed (0x1A)`: это запрос доверия к нашему новому EFI-файлу. Нажать OK, войти в MOK Manager, выбрать **Enroll hash from disk** → системный EFI-раздел → `EFI` → `ArasakaAnim` → **grubx64.efi** → Continue → Yes. Не выбирать отключение Secure Boot или доверие ко всему сертификату.
3. Ожидаемый SHA256 PE/COFF, который показывает MOK (это не обычный хеш всего файла):

```text
bb87946dd1f8f4abc291051c2456e7fb4a4829b20d5062dd248d2594d40802eb
```

4. После регистрации MOK перезагрузится. Одноразовый выбор уже израсходован: может загрузиться прежний HackBGRT. Тогда войти в Windows и **ещё раз запустить `Test-Arasaka-Animation.cmd`**. Это нормально и не означает, что анимация не установилась.
5. При втором старте посмотреть на маленький индикатор под большим логотипом. Должен двигаться ободок/сегменты вокруг неподвижного знака Arasaka. Сам статичный рисунок полосы в большом логотипе не оживает.

Обычный постоянный порядок загрузки не меняется. После теста следующий обычный запуск снова идёт прежним путём. Для теста включается отображение boot UI; `Cancel-Arasaka-Test.cmd` возвращает прежнее скрытие индикатора и отменяет ещё не использованный тест.

## Если что-то пошло не так

- Эксперимент не перезаписывает `EFI\Microsoft\Boot\bootmgfw.efi`, `Windows\System32\winload.efi`, обычные `Boot\Fonts` и старую папку HackBGRT. Не нужно восстанавливать все файлы Windows из старого снимка.
- При сбое до входа в систему открыть меню загрузки UEFI и выбрать **Windows Boot Manager**. Одноразовая запись обычно уже израсходована; не выбирать Arasaka Animation повторно. Это независимый путь обхода экспериментального модуля до запуска Windows.
- После входа, в том числе в безопасном режиме, запустить **Restore-Arasaka-Animation.cmd**. Он удалит только экспериментальную запись и созданные им файлы с совпадающими хешами, вернёт прежний `bootuxdisabled`. Изменённые кем-то ещё файлы оставит для проверки.
- **Cancel-Arasaka-Test.cmd** отменяет ожидающий тест и возвращает прежний boot UI, но оставляет пакет установленным.
- MOK-хеш после удаления пакета остаётся записью доверия к единственному удалённому бинарнику; откат не трогает общую базу MOK или ключи Secure Boot. Если нужен полный отзыв доверия, удалить именно этот хеш через MOK Manager, сохранив существующее доверие HackBGRT.

## FACEIT

Существующий **Restart-For-FACEIT.cmd** запускает следующий старт напрямую через штатный Windows Boot Manager. Экспериментальный EFI-модуль при этом не выполняется, используются оригинальные шрифты и бинарники. Secure Boot не отключается; BCD `testsigning`, `nointegritychecks`, `debug` не включаются. Сам античит в этой работе не запускался, поэтому совместимость не объявляется подтверждённой.

Если сначала был вручную выставлен тест, но перезагрузка ещё не случилась, выполнить `Cancel-Arasaka-Test.cmd`, затем `Restart-For-FACEIT.cmd`: скрипты намеренно не перезаписывают чужой ожидающий BootNext.

## Файлы и проверка

- Пакет: `%USERPROFILE%\CyberDeck\boot-animation-v1`.
- Журнал и снимок BCD: `%USERPROFILE%\CyberDeck\backup\boot-animation-v1`.
- Управление: `Manage-Boot-Animation.ps1 -Action Check|TestRoundTrip|ArmTest|CancelTest|Restore`.
- `Check` проверяет Secure Boot, исходные файлы, ресурсы пакета и путь загрузочной записи.
- `TestRoundTrip` выставляет и убирает BootNext, включает и возвращает boot UI, без команды перезагрузки.
- После обновления Windows проверка может отказать из-за новых хешей. Не обновлять эталон автоматически: сначала пересмотреть новые версии загрузчиков.
