# Arasaka: загрузка, оформление и автозапуск

## Переключение загрузки

Скопировать `Switch-Verified-Boot-Mode.ps1` в `%USERPROFILE%\CyberDeck`, а `Boot-FACEIT.cmd` и `Boot-Arasaka.cmd` на рабочий стол.

- **Boot-FACEIT.cmd** ставит Windows Boot Manager первым в UEFI.
- **Boot-Arasaka.cmd** находит единственную запись `\EFI\HackBGRT\loader.efi` и ставит её первой.
- Нужны права администратора. Автоматической перезагрузки нет. Изменение действует при следующем старте и сохраняется до обратного переключения.
- `-CheckOnly` проверяет наличие записи без изменения порядка. Логи и исходный порядок — `CyberDeck\backup\boot-switch`.

Secure Boot остаётся включённым. Темы рабочего стола и Steam не переключаются. Самоподписанный загрузчик может не пройти [аттестацию FACEIT](https://support.faceit.com/hc/en-us/articles/20669555338268-TPM-attestation-failed), поэтому режим FACEIT использует штатную цепочку. Успех запуска античита требует отдельной проверки после перезагрузки; это не обход античита.

## Оптимизация

`Optimize-Startup.ps1` сохраняет и удаляет только выбранные записи HKCU Run: Spotify, EA, LM Studio, Roblox, предзапуск Edge и Yandex. Уже запущенные приложения не закрывает. Повторное применение с существующей резервной копией блокируется. `-Undo` возвращает записи.

На этом ПК отдельно сохранён `powercfg /getactivescheme` в `CyberDeck\backup\power-before-optimization.txt`, затем включён `SCHEME_BALANCED` вместо Silent. `Restore-Optimization.cmd` запускает восстановление автозапуска и исходной схемы через `Restore-Optimization.ps1`; оба PS1 должны находиться в CyberDeck. Измеренного прироста FPS или сокращения загрузки пока нет.

## Иконки и часы

1. `Build-Theme-Addons.ps1` собирает исходники из `vendor` установленным компилятором Windhawk 1.7.3.
2. `python build-icon-resources.py --icons "$env:USERPROFILE\CyberDeck\icons" --output "$env:USERPROFILE\CyberDeck\icon-resources"` создаёт DLL только с ресурсами и theme.ini. Команда предназначена для PowerShell.
3. `Install-Theme-Addons.ps1` устанавливает Resource Redirect только в Explorer и Clock Styler только в LockApp, применяет существующие стили Arasaka. Требует отсутствия этих двух модов, чтобы не затереть чужие настройки.
4. `-Disable` отключает оба мода; аварийный CMD тоже их охватывает. Затем открыть новый сеанс, чтобы сбросить кэш процессов. Скрипты не блокируют ПК и не перезагружают его.

Ресурсы Windows не заменяются. Подменяются известные ресурсы главной страницы, галереи, компьютера, сети, корзины и пользовательских папок. Это не все значки всех программ Windows. OneDrive дополнительно настроен через apply-icons.ps1. Закреплённому File Explorer.lnk на этом ПК назначен thispc.ico; оригинал сохранён в CyberDeck\backup\File Explorer.lnk.

Проверка 12.11.2026: в живом Проводнике основные значки красные, полосы дисков красные, мод Resource Redirect загружен. Фон блокировки подтверждён через WinRT, часы сконфигурированы; реальный экран блокировки пока не проверен. Startup Sound Changer и пользовательский звук не затронуты.

## Надписи выключения и курсоры — обновление 12.11.2026

Пользователь подтвердил, что экспериментальный перехват LogonUI не убрал надпись выключения. Теперь `apply-session-art.ps1` включает документированную политику `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\DisableStatusMessages=1`. Она скрывает сообщения запуска, выключения, входа и выхода: [Microsoft ADMX_Logon](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-logon#disablestatusmessages). Применение проверено чтением реестра; эффект на настоящем выключении ещё не проверен. Причина неудачи ABI-хуков не установлена; новые хуки не добавлялись.

`make-boot-art.ps1` создаёт 640×480 BMP с логотипом и красными сегментами загрузки. **Изображение статическое**, это не анимация и не показ реального прогресса. HackBGRT подменяет BGRT-картинку; заменить анимацию Windows таким способом нельзя. Скрипт применения меняет только установленный splash.bmp, проверяет хеш и неизменность Windows bootmgfw.efi. Secure Boot и порядок загрузки не меняет, ПК не перезагружает. В режиме FACEIT этот рисунок не используется.

Для применения: сгенерировать BMP, сохранить как `CyberDeck\boot-v2-splash.bmp`, затем запустить `apply-session-art.ps1`. Он монтирует EFI на свободную S: только на время операции; при занятой S: останавливается. Исходные картинки и значение политики сохраняются в `CyberDeck\backup\session-art-v2`; `-Undo` возвращает их. Конфигурацию HackBGRT и EFI-программы скрипт не переписывает.

`make-arasaka-cursors.ps1 -OutDir "$env:USERPROFILE\CyberDeck\cursors-v2"` рисует 17 ролей: CUR 32/48/64 и двенадцатикадровые ANI для ожидания и фоновой работы. Внутри Windows анимация настоящая; она не относится к ранней загрузке. `apply-arasaka-cursors.ps1` проверяет все файлы нативным LoadImage перед записью в реестр, сохраняет прежние значения в backup/cursors-v2.json и обновляет курсоры через SPI_SETCURSORS. `-Undo` восстанавливает предыдущий набор. Основной apply.ps1 использует этот комплект при следующей установке.

`Restore-Session-Art.cmd` на рабочем столе возвращает предыдущие boot-картинку, политику и курсоры. Оба apply-скрипта для него находятся в CyberDeck. Просмотрены PNG-предпросмотры; все 17 курсоров загружены Windows без ошибки. Реальный цикл загрузки/выключения пользователю ещё предстоит проверить.

## Проверяемое переключение и возврат порядка загрузки — 12.11.2026

Boot-FACEIT.cmd и Boot-Arasaka.cmd теперь вызывают Switch-Verified-Boot-Mode.ps1. Он проверяет Secure Boot, стандартные пути Boot Manager/current winload, отсутствие включённых BCD-флагов testsigning/nointegritychecks/debug/bootdebug, подписи пяти файлов (Boot Manager, winload, kernel, два Windows-шрифта) и хеши семи файлов, включая два EFI-шрифта. EFI-шрифты проверяются по сохранённым хешам: стандартный поставщик Authenticode не распознаёт их формат. Это ограниченная проверка известной цепочки, не полная аттестация FACEIT и не сканер всех драйверов.

При первом запуске сохраняется CyberDeck/backup/boot-switch/verified-baseline-v2.json с исходным порядком и хешами. После обновления Windows несовпадение хеша остановит переключение с записью error.txt; базовая копия автоматически не перезаписывается. Требуется проверить причину и заново зафиксировать исходное состояние, а не вернуть устаревшие системные файлы.

Restore-Boot-Mode.cmd на рабочем столе вызывает -Mode Restore: возвращает сохранённый порядок UEFI с обратным чтением. При неудаче записи переключатель пытается вернуть порядок до вызова. Этот откат относится ТОЛЬКО к порядку загрузки: он не чинит повреждённые системные файлы и не является откатом ещё не установленной анимации. Если Windows не запускается, доступный независимый путь — выбрать штатный Windows Boot Manager в меню UEFI, пока его файлы остаются неизменными. Для восстановления общих файлов после возможного будущего эксперимента нужен отдельный проверенный механизм.

Secure Boot включён, ПК не перезагружался, запуск самого FACEIT не проверялся. Скрипт установлен в CyberDeck, три CMD на рабочем столе. Старые простые переключатели сохранены в проекте для истории, новые CMD на них не ссылаются.
